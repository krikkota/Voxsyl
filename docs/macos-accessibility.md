# Разрешение горячей клавиши после обновления Voxsyl

14 октября 2026. Первые локальные сборки использовали ad-hoc подпись. `codesign -d -r- Voxsyl.app` показал правило `designated => cdhash H"…"`: оно соответствует одной конкретной сборке. После пересборки хеш меняется, а строка Voxsyl в «Универсальном доступе» может остаться включённой для прежнего приложения. Полный перезапуск текущей сборки проблему пользователя не устранил.

## Исправление сборки

`app/dev_signing.py --initialize` однократно создаёт отдельный локальный сертификат для разработки и приватный ключ в `.local/dev-signing/voxsyl-dev.keychain-db`. Новый ключ не импортируется в личную login keychain и не добавляет системного доверия. Связка временно добавляется в search list только во время подписи; список восстанавливается после операции. Пароль хранится локально с правами 0600, каталог имеет права 0700. Этот каталог не является одноразовым кешем: его удаление изменит идентичность следующих сборок.

После Tauri-bundling `app/build.py` подписывает конечное приложение правилом:

```text
identifier "org.voxsyl.prototype" and certificate leaf = H"<fingerprint сертификата>"
```

Постоянство bundle ID без привязки к сертификату не используется. При недоступном ключе сборка останавливается; автоматического возврата к ad-hoc нет. Перед обновлением нужно завершить Voxsyl через ⌘Q. Скрипт не заменяет работающий процесс и восстанавливает предыдущий bundle при ошибке сборки/подписи.

Механизм идентичности и обновлений описан в [Apple TN2206](https://developer.apple.com/library/archive/technotes/tn2206/_index.html). Это локальная разработческая подпись, не Developer ID и не notarization.

## Однократный переход со старой подписи

1. Полностью завершить Voxsyl через ⌘Q.
2. Открыть «Системные настройки → Конфиденциальность и безопасность → Универсальный доступ».
3. Удалить старую запись Voxsyl кнопкой «−», затем кнопкой «+» добавить текущий `Voxsyl.app` из `app/src-tauri/target/debug/bundle/macos/` и включить его.
4. Запустить Voxsyl снова.

Из окна выбора файла к каталогу удобно перейти через ⌘⇧G и абсолютный путь. Если ранее создано несколько копий приложения, добавлять ту же копию, которая затем запускается. Обычное закрытие окна оставляет приложение в строке меню, поэтому нужен именно ⌘Q.

Само приложение не выдаёт себе доступ и не меняет TCC.db. Полный сброс разрешений других программ не нужен. В следующей серии пересборок на том же Mac доступ сохранился: после штатного запуска реальная вставка в TextEdit прошла, повторного подтверждения не потребовалось. ## Диагностика в приложении

Статус `permission_required` берётся из `AXIsProcessTrusted`, а не из наличия зарегистрированной клавиши. Если доступ есть, но создание listener или регистрация сочетания не удались, показывается отдельное сообщение «Горячая клавиша недоступна». При отзыве доступа старый manager удаляется; после возврата доступа создаётся заново. Активная запись при отзыве доступа отменяется.

`python3 app/dev_signing.py --verify-update-identity` подписывает два разных временных бинарника, не запуская их. Проверка требует разных cdhash и одинакового certificate-bound designated requirement. Отчёт: `outputs/dev-signing-verification.json`. Это проверка подписи, а не подтверждение выдачи или сохранения пользовательского разрешения.
